# 正则表达式调试器设计

## 目标

在现有测试工具聚合页中增加“正则表达式调试器”。用户输入 JavaScript 正则表达式、Flags 和测试文本后，页面实时展示匹配高亮、匹配详情和替换结果预览。

工具继续保持现有 Vite 纯前端、静态部署和 PWA 离线使用模式。正则与测试文本仅在当前浏览器中处理，不上传服务器。

## 范围

本次包含：

- 使用浏览器原生 JavaScript `RegExp` 语义。
- 支持 `g`、`i`、`m`、`s`、`u`、`y` Flags。
- 输入变化后约 120ms 防抖并实时执行。
- 高亮匹配结果，并展示匹配数量、索引、完整匹配、捕获组和命名捕获组。
- 支持 JavaScript 替换模板并实时预览替换结果，包括 `$&`、`$1`、`$<name>` 等语法。
- 处理非法表达式、零长度匹配和过多匹配等边界情况。
- 正则逻辑专项验证、现有工具回归验证和项目构建验证。

本次不包含：

- PCRE、Java、Python、Go 等其他正则方言。
- 正则语法树、逐字符执行轨迹或回溯过程可视化。
- 正则表达式自动生成、AI 解释或优化建议。
- 历史记录、收藏、持久化或云端同步。
- 后端接口或第三方在线正则服务。

## 页面与交互

### 入口位置

在现有侧栏“格式与时间”分类中增加“正则表达式调试器”入口。点击入口后滚动到对应工具分区，不新增页面或路由。

### 输入区

工具卡片包含：

1. **正则表达式**：输入表达式正文，不要求用户填写首尾 `/`。
2. **Flags**：`g`、`i`、`m`、`s`、`u`、`y` 独立选择，默认启用 `g`。
3. **测试文本**：多行文本输入框。
4. **替换模板**：可选的多行文本输入框，按 JavaScript `String.prototype.replace` 模板语义处理。
5. **清空**：恢复默认 Flag，仅保留 `g`，并清空所有输入、错误和结果。

正则表达式、Flags、测试文本或替换模板变化后，页面经过约 120ms 防抖自动重新计算，不设置额外“执行匹配”按钮。

### 输出区

计算成功后展示：

- 已收集的匹配数量；达到展示上限时明确标记结果已截断，不把该数量误报为完整总数。
- 保留测试文本换行和空格的高亮预览。
- 每个匹配的序号、起始索引、完整匹配内容。
- 各数字捕获组的编号、内容以及未参与匹配状态。
- 命名捕获组的名称、内容以及未参与匹配状态。
- 使用当前正则和替换模板生成的完整替换结果预览。

未启用 `g` 时遵循 JavaScript 语义，只展示第一个匹配，替换也只处理第一个匹配。启用 `g` 时展示并替换所有匹配，但详情最多展示前 500 个匹配。

### 高亮规则

- 普通非空匹配使用 `<mark>` 高亮。
- 多个匹配按原文索引顺序渲染，不改变原始文本内容。
- 零长度匹配使用可见的位置标记，显示在对应字符边界，不伪造被匹配字符。
- 用户输入通过文本节点或 `textContent` 渲染，不将原始文本直接拼接进 `innerHTML`。

## 架构与组件

### 页面层

在 `index.html` 中新增侧栏入口、输入控件、高亮预览、匹配详情、替换预览和错误区域。样式追加到 `src/style.css`，复用现有卡片、按钮、输入框、错误提示和响应式布局模式。

### 交互层

在 `src/main.js` 中负责：

- 读取输入和 Flag 状态。
- 管理约 120ms 防抖。
- 调用正则计算模块。
- 渲染匹配高亮、零长度位置、匹配详情和替换预览。
- 管理空白、成功、错误、截断和清空状态。

### 正则计算模块

新增 `src/regexDebugger.js`，模块不访问 DOM。对外提供统一接口：

```text
debugRegex({
  pattern,
  flags,
  testText,
  replacement,
  maxMatches
})
```

成功结果：

```text
{
  matches,
  matchCount,
  truncated,
  replacementResult
}
```

每个匹配项包含：

```text
{
  index,
  value,
  endIndex,
  groups,
  namedGroups,
  isZeroLength
}
```

模块使用浏览器原生 `RegExp`，不引入新的正则依赖。匹配详情与替换结果必须基于同一组 Pattern 和 Flags。

## 数据流

1. 用户修改 Pattern、Flags、测试文本或替换模板。
2. 页面重置防抖计时器，并在约 120ms 后读取最新输入。
3. 正则模块创建原生 `RegExp`，并执行匹配。
4. 非全局模式只收集第一条匹配；全局模式持续收集，最多记录前 500 条详情。
5. 遇到零长度匹配时按 Unicode 模式规则推进 `lastIndex`，避免无限循环或跳过代理对中的字符。
6. 模块使用相同的 Pattern 和 Flags 生成替换结果。
7. 页面安全地渲染高亮、匹配详情和替换预览。

整个流程在浏览器本地完成，不调用远程接口。

## 校验与异常处理

校验和处理规则：

- Pattern 为空时视为未开始调试，显示空白引导，不创建可匹配所有位置的空正则。
- 重复或不支持的 Flag 不会由界面产生；模块仍需校验并返回明确错误。
- 正则语法错误显示浏览器提供的错误信息，并加中文前缀“正则表达式无效”。
- 发生错误时保留用户输入，清空旧匹配、高亮和替换结果。
- 零长度全局匹配必须主动推进索引，避免无限循环。
- 全局匹配最多记录 500 条详情；达到上限后停止继续枚举，显示“仅展示前 500 条匹配”。
- 替换模板为空字符串时仍执行替换预览，结果表示删除命中内容。
- 测试文本为空时返回零匹配和空替换结果，不报错。
- 防抖回调只渲染执行时读取到的最新输入状态。

## 验收标准

1. 侧栏和工具分区均显示“正则表达式调试器”，入口可正常滚动定位。
2. 默认启用 `g`，其余 Flags 默认关闭。
3. 输入变化后无需点击按钮即可实时刷新结果。
4. `g`、`i`、`m`、`s`、`u`、`y` 按浏览器 JavaScript 语义生效。
5. 普通匹配在原测试文本中准确高亮，换行和空格得到保留。
6. 零长度匹配有可见位置标记且不会造成死循环。
7. 匹配详情准确显示索引、完整匹配、数字捕获组和命名捕获组。
8. 替换预览支持 `$&`、`$1` 和 `$<name>` 等 JavaScript 替换模板。
9. 未启用 `g` 时只匹配和替换第一处，启用 `g` 时处理全部命中。
10. 非法正则显示明确错误，且不会继续显示旧结果。
11. 匹配超过 500 条时停止枚举并明确提示结果已截断。
12. 用户文本按纯文本安全渲染，HTML 标签或脚本内容不会作为页面结构执行。
13. 清空后恢复默认 Flag 和空白结果。
14. 工具首次联网加载并缓存后可按现有 PWA 机制离线使用。

## 验证

新增正则计算模块专项验证脚本和对应 npm 命令，至少覆盖：

- 普通单次匹配和全局匹配。
- `i` 大小写、`m` 多行、`s` 点号跨行、`u` Unicode 和 `y` 粘连模式。
- 数字捕获组、可选捕获组和命名捕获组。
- 普通零长度匹配和 Unicode 文本中的零长度匹配。
- Pattern 为空、测试文本为空和非法正则。
- `$&`、`$1`、`$<name>` 以及空替换模板。
- 500 条匹配详情上限和截断标记。
- 包含 HTML 标签或脚本字符串的输入只作为文本输出。

实现完成后运行正则专项验证、现有工具的 npm 回归命令和：

```powershell
npm run build
```

随后在浏览器中检查侧栏入口、实时刷新、Flags、错误提示、高亮、捕获组、替换预览、清空操作和移动端布局。

## 可见结果

测试工具聚合页新增“正则表达式调试器”。用户输入 JavaScript 正则、Flags、测试文本和可选替换模板后，可以立即看到安全高亮的匹配结果、每条匹配及捕获组详情，以及完整替换结果；整个过程不依赖后端或第三方服务。
