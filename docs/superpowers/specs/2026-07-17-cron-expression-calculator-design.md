# Cron 表达式计算工具设计

## 目标

在现有测试工具聚合页中增加“Cron 表达式计算”工具。用户选择 Cron 类型并输入表达式后，浏览器在本地校验表达式、生成中文描述，并按浏览器当前时区计算未来执行计划。

工具首期完整支持 Linux、Cron4j、Quartz 和 Spring 四种 Cron 类型，继续保持现有 Vite 纯前端、静态部署和 PWA 离线使用模式。

## 范围

本次包含：

- 四种 Cron 类型的选择、字段校验和执行时间计算。
- 查看数量设置，默认 5 次，允许 1–50 次。
- 从用户点击“查看执行计划”时的当前时间开始计算。
- 中文表达式描述；无法准确自然概括时，展示字段级结构化描述。
- 未来执行时间列表、浏览器时区标识、清空操作和中文错误提示。
- 四种类型的字段结构、允许值和特殊字符说明。
- Cron 计算模块专项验证、项目构建和页面交互验证。

本次不包含：

- Cron 可视化生成器。
- 常用表达式预设、收藏、历史记录或配置持久化。
- `@daily`、`@reboot` 等 Linux 宏。
- Linux crontab 用户、命令或环境变量解析。
- 任务创建、服务端调度、接口调用和账号能力。
- 用户选择时区；首期只使用浏览器当前时区。

## 页面与交互

### 入口位置

在现有侧栏“格式与时间”分类中增加“Cron 表达式计算”入口，放在“时间戳转换”附近。点击入口后滚动到对应工具分区，不新增独立页面或路由。

### 输入区

工具卡片包含：

1. **Cron 类型**：Linux、Cron4j、Quartz、Spring，默认 Quartz。
2. **查看数量**：数字输入框，默认 5，允许 1–50 的整数。
3. **Cron 表达式**：单行文本输入框，根据当前类型展示字段格式提示。
4. **操作按钮**：“查看执行计划”和“清空”。

切换 Cron 类型时保留已输入表达式，不自动改写；用户再次计算时按新类型重新校验。

### 输出区

计算成功后展示：

- 表达式中文描述。
- 浏览器实际时区，例如 `Asia/Shanghai`。
- 按时间升序排列的未来执行计划。
- 每条时间使用 `YYYY-MM-DD HH:mm:ss 星期X` 格式。

用户修改类型、数量或表达式后，旧结果保留到下一次计算，但结果区标记“结果基于上次计算”，避免把旧结果误认为自动更新后的结果。

### 清空

“清空”不需要二次确认，执行后：

- Cron 类型恢复为 Quartz。
- 查看数量恢复为 5。
- 表达式、描述、执行计划和错误提示全部清空。

### 使用说明

工具区域展示：

- 四种类型的字段结构。
- 各字段允许值。
- `*`、`?`、`-`、`,`、`/`、`L`、`W`、`#` 的含义和适用字段。
- 不同类型的星期编号差异。

## Cron 类型规则

| 类型 | 字段结构 | 规则边界 |
| --- | --- | --- |
| Linux | `minute hour dayOfMonth month dayOfWeek` | 固定 5 个时间字段；星期支持 0–7，0 和 7 均表示星期日 |
| Cron4j | `minute hour dayOfMonth month dayOfWeek` | 固定 5 个字段；星期按 Cron4j 规则使用 0–6 |
| Quartz | `second minute hour dayOfMonth month dayOfWeek [year]` | 6 个必填字段，可选年份；星期按 Quartz 规则使用 1–7 |
| Spring | `second minute hour dayOfMonth month dayOfWeek` | 固定 6 个字段；星期支持 0–7 |

共同规则：

- 支持数字以及月份、星期英文缩写，如 `JAN`–`DEC`、`SUN`–`SAT`。
- 分别支持对应类型允许的 `*`、`?`、`-`、`,`、`/`、`L`、`W`、`#`。
- 特殊字符必须结合 Cron 类型和所在字段校验，不能只检查字符集合。
- Quartz 只在提供第七个字段时解析年份。
- 四种类型分别遵循自己的星期编号、日期匹配和特殊字符语义，不将其强制转换为同一套规则。
- Linux 输入只允许 5 个时间字段，不接受后续用户或命令内容。

如果表达式合法但不能准确转换为一句自然语言，描述区必须展示字段级结构化说明，不能输出可能误导用户的简化描述。

## 架构与组件

### 页面层

在 `index.html` 中新增侧栏入口、工具卡片、描述区、执行计划区和语法说明。页面沿用现有卡片、按钮、输入框和结果区风格。

### 交互层

在 `src/main.js` 中负责：

- 读取用户输入。
- 调用 Cron 计算模块。
- 管理计算中、成功、错误、结果已过期和清空状态。
- 渲染中文描述、时区和执行计划。

### Cron 计算模块

新增独立模块，负责四种类型的解析、校验、描述和执行时间计算，不直接访问 DOM。对外提供统一接口：

```text
calculateCronSchedule({
  type,
  expression,
  count,
  startTime,
  timeZone
})
```

成功结果：

```text
{
  description,
  executions,
  timeZone
}
```

内部按 Linux、Cron4j、Quartz、Spring 分别适配，避免把四种规则混入页面事件代码。中文描述与执行时间必须基于同一次解析结果。

第三方解析库只有在确认满足以下条件后才能采用：

- 能被 Vite 打包并在浏览器离线运行。
- 对目标 Cron 类型和特殊字符的语义有可验证的支持。
- 不调用远程接口，不依赖 Node.js 服务端运行时。

如果候选库不能覆盖全部规则，缺失部分必须在适配层明确实现，不能通过放宽校验或类型断言掩盖差异。

## 数据流

1. 用户选择 Cron 类型、输入查看数量和表达式。
2. 用户点击“查看执行计划”。
3. 页面记录点击时的当前时间和浏览器时区。
4. 页面校验查看数量，并将表达式首尾空格去除、连续空白视为字段分隔符。
5. Cron 模块按所选类型解析和校验表达式。
6. Cron 模块基于同一解析结果生成描述和未来执行时间。
7. 页面展示描述、时区和执行计划。

整个流程在浏览器本地完成，不上传表达式，不调用参考网站或其他在线接口。

## 校验与异常处理

校验顺序：

1. Cron 类型。
2. 查看数量是否为 1–50 的整数。
3. 表达式是否为空。
4. 当前类型要求的字段数量。
5. 各字段取值范围。
6. 特殊字符的位置和组合。
7. 未来执行时间是否可计算。

错误处理：

- 表达式为空：提示“请输入 Cron 表达式”。
- 查看数量不合法：提示“查看数量必须是 1–50 的整数”。
- 字段数量错误：提示当前类型要求的字段结构。
- 数值越界：指出具体字段及允许范围。
- 特殊字符不受当前类型或字段支持：指出字符和字段。
- 表达式不存在有效执行时间：明确提示，不无限计算。
- 计算失败：保留用户输入，清空旧描述和旧执行结果。
- 计算期间禁用计算按钮；成功或失败后恢复。
- 所有错误显示在工具区域内，不使用浏览器弹窗。

计算模块必须设置搜索上限。复杂、无解或在可计算范围内无法找到足够结果的表达式到达上限后立即停止；如果已经找到部分结果，则展示已找到结果并说明未达到请求数量。

## 验收标准

1. Linux、Cron4j、Quartz、Spring 均能识别合法表达式并生成正确执行时间。
2. 默认类型为 Quartz，默认查看数量为 5。
3. 查看数量仅接受 1–50 的整数。
4. 计算从点击按钮时的当前时间开始，不返回已经过去的执行时间。
5. 正常情况下返回的结果数量与用户设置一致；无法达到时明确说明。
6. 每条结果展示日期、时间和星期，结果区显示浏览器实际时区。
7. 表达式描述与执行计划语义一致。
8. 切换类型后按新类型重新校验，不自动修改原表达式。
9. 清空后恢复默认类型、默认数量和空白结果。
10. 非法输入均有明确中文提示，且不会展示旧结果。
11. 复杂或无解表达式在搜索上限内终止，不造成页面持续卡死。
12. 工具首次联网加载并缓存后可按现有 PWA 机制离线使用。

## 验证

新增 Cron 模块专项验证脚本和对应 npm 命令，至少覆盖：

- Linux：通配符、范围、列表、步长、月份与星期英文缩写、星期日 0/7。
- Cron4j：5 字段、星期 0–6、范围和步长。
- Quartz：6 字段、7 字段年份、`?`、`L`、`W`、`#`。
- Spring：6 字段、步长、星期英文缩写及其支持的特殊字符。
- 时间边界：跨分钟、跨天、跨月、跨年、闰年和不同月份天数。
- 时区：页面显示的浏览器时区与计算时区一致。
- 非法输入：空值、字段数错误、越界、错误特殊字符位置和不可能日期。
- 状态变化：切换类型、修改表达式、重复计算、失败后重试和清空。
- 性能保护：复杂或无解表达式在搜索上限内终止。

实现完成后运行：

```powershell
npm run test:cron
npm run build
```

随后在 Google Chrome 中进行页面验证，检查导航、输入、错误提示、结果展示、时区、移动端布局和离线缓存。

## 可见结果

测试工具聚合页侧栏出现“Cron 表达式计算”。用户选择类型、输入查看数量和表达式后，可以看到该表达式的中文描述，以及按浏览器当前时区计算的未来执行时间；整个过程不依赖后端或外部网站。
