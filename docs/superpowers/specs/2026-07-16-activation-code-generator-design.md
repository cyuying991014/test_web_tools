# 激活码生成工具设计

## 目标

在现有测试工具聚合页中增加“激活码生成”工具。用户输入公司内部产品的关键字后，浏览器在本地生成兼容现有 Go 算法的激活码。项目继续保持 Vite 纯前端架构，并可按现有方式部署到 GitHub Pages。

## 范围

本次包含：

- 将 `main.go` 中的激活码算法等价移植为浏览器端 JavaScript。
- 修复原实现仅计算补齐长度、但没有实际补零导致的越界问题。
- 在现有侧栏和工具页中增加“激活码生成”入口与操作卡片。
- 增加算法专项验证脚本并执行项目构建验证。

本次不包含：

- Go 后端、第三方接口或网络请求。
- GitHub Pages 部署配置调整。
- 现有工具的重构或无关样式调整。

## 架构

### 算法模块

新增 `src/activationCode.js`，导出 `generateActivationCode(keyword)`。模块负责：

1. 使用 `TextEncoder` 将关键字转换为 UTF-8 字节。
2. 在关键字前写入 4 字节大端长度。
3. 将完整字节序列补零到 8 字节整数倍。
4. 使用 JavaScript `BigInt` 和显式 32 位运算移植轮密钥、加密、解密与循环移位逻辑。
5. 使用 `crypto.getRandomValues()` 生成非负 31 位随机后缀，保持同一关键字可生成不同有效结果的行为。
6. 返回 18 位小写十六进制激活码。

算法模块不访问 DOM，也不发送网络请求。

### 页面集成

在 `index.html` 中：

- 在侧栏加入“激活码生成”锚点。
- 新增与现有工具一致的卡片，包含关键字输入框、生成按钮、复制按钮和只读结果区域。
- 明确提示关键字仅在当前浏览器中处理。

在 `src/main.js` 中：

- 导入 `generateActivationCode`。
- 绑定点击生成与 Enter 生成事件。
- 复用现有 `showToast` 和复制能力。
- 生成失败时清除旧结果，避免用户复制过期激活码。

不新增独立页面、路由或样式体系。仅在现有通用样式不足时增加最小的局部样式。

## 数据流

1. 用户输入关键字。
2. 页面使用 `trim()` 判断输入是否为空，但把未经裁剪的原始字符串传给算法，因此首尾空格属于关键字内容。
3. 算法模块按 UTF-8 字节长度编码并补零。
4. 算法模块生成随机后缀并计算激活码。
5. 页面显示结果并启用复制按钮。

整个流程在浏览器本地完成，没有接口调用和数据上传。

## 异常处理

- 输入为空或仅含空白：不生成，并提示用户输入关键字。
- 浏览器缺少 `TextEncoder`、`BigInt` 或安全随机数能力：显示不支持提示，并保持复制按钮禁用。
- 算法计算异常：清空旧结果、显示失败提示，不输出部分结果。
- 复制失败：沿用现有复制失败提示，允许用户手动选择结果。

## 兼容性规则

- 输入长度使用 UTF-8 字节数，而不是 JavaScript 字符数。
- 数值计算必须模拟 Go 的 `int32`、`int64`、无符号右移和溢出行为。
- 补零后的数据长度必须是 8 字节整数倍，支持任意 UTF-8 关键字长度。
- 随机后缀范围与 Go `rand.Int31()` 一致，为 `0` 至 `2^31 - 1`。
- 输出固定为 18 位小写十六进制字符。

## 验证

新增 `scripts/verify-activation-code.mjs`，并在 `package.json` 增加 `test:activation-code`。验证覆盖：

- `test`：覆盖原实现可直接处理的整块长度。
- `charles`：覆盖需要补零的非整块长度。
- 中文关键字：覆盖 UTF-8 多字节编码。
- 固定随机后缀的已知结果：验证 JavaScript 移植与参考算法一致。
- 空输入：验证拒绝逻辑。
- 多次生成及格式断言：验证结果为 18 位小写十六进制字符串。

实现完成后运行：

```powershell
npm run test:activation-code
npm run build
```

如本机环境允许，再启动 Vite 开发服务器并确认首页返回 HTTP 200、工具可生成及复制结果。

## 可见结果

工具聚合页侧栏出现“激活码生成”。用户进入该区域、输入任意非空关键字并点击生成后，会看到一个 18 位小写十六进制激活码；重复生成允许得到不同结果。关键字不会离开浏览器。
