# 需求文档：测试常用工具聚合页（MVP）

## 1. 文档信息

| 项 | 说明 |
| --- | --- |
| 文档状态 | **迭代中**（在原会话定稿基础上补充实现与交互说明） |
| 产品形态 | 独立 Web 页面，集成多个本页内小工具 |
| 发布范围 | 第一期包含本文档 **第 5 节** 所列全部工具与能力 |

---

## 2. 背景与目标

测试人员在执行测试时，经常需要临时使用各类小工具（如 MD5、JSON 格式化、时间戳转换等）。当前依赖搜索或分散书签，打开路径长、效率低。

**目标**：提供**单一入口**的独立网页，在需要时快速打开并使用常用工具，**全部为浏览器端处理**，不依赖外部工作流与业务系统。

**成功标准**：无强制量化指标；交付物为可用、符合验收标准的网页即可。

---

## 3. 用户与使用场景

| 维度 | 说明 |
| --- | --- |
| 用户 | 主要为**个人使用**；暂不区分角色与权限 |

| 与工作流 | **独立**，不与 Jira、用例平台、CI 等做联动或嵌入 |

## 4. 范围说明

### 4.1 本期包含

- 下文 **第 5 节** 所列全部工具能力（含：**MD5、JSON、时间与时间戳互转、进制转换、文本/JSON 比较、颜色互转** 等），均在站内提供。
- 全站 **简体中文** 界面与提示文案。

### 4.2 本期明确不包含

- 用户登录、账号体系。
- 工具配置持久化（如自定义链接、个人布局）；**不需要配置能力**。
- 多环境（测试/预发/生产）切换与 Base URL 管理。
- 视觉规范与品牌定制（颜色、字体、组件库规范等**可不单独成册**；实现可采用项目统一风格）。
- 与工作流、内网系统、敏感参数的集成；页面**不包含内网地址与敏感参数**相关能力。

## 5. 功能需求（按工具）

### 5.1 文件 MD5 计算

| 项 | 说明 |
| --- | --- |
| 能力 | 用户上传本地文件，页面计算并展示该文件的 **MD5 摘要**；**不在服务端存储文件**，仅内存/流式计算（实现方式由研发选型）。 |
| 单文件大小 | **不超过 200 MB**；超出时明确提示，不执行计算或中止并提示。 |
| 上传方式 | **点击选择文件** + **拖拽文件到指定区域**。 |
| 输出 | 展示 MD5 字符串；提供 **一键复制** 结果（结果区旁单独按钮亦可）。 |
| 说明 | MD5 输出格式：**小写十六进制**（无需大小写切换）。 |

### 5.2 文本转 MD5

| 项 | 说明 |
| --- | --- |
| 能力 | 用户在文本框输入内容，按 **UTF-8 编码** 对文本字节序列计算 MD5 并展示。 |
| 输出 | 展示 MD5；提供 **一键复制**。 |
| 说明 | 与「文件 MD5」一致：**小写十六进制**；无需大小写选项。 |

### 5.3 JSON 文本格式化与浏览

#### 5.3.1 解析与合法性

| 项 | 说明 |
| --- | --- |
| 能力 | 用户粘贴 JSON 字符串，校验语法；合法则进入 **可视化浏览** 与 **可复制美化文本**。 |
| 缩进 | 导出/复制为文本时，**2 个空格** 每层缩进（`JSON.stringify(..., null, 2)` 语义）。 |
| 非法 JSON | **明确提示**错误信息；不展示树状视图；可提供占位说明引导用户修正。 |

#### 5.3.2 树状展示与折叠

- 合法 JSON 以 **树状结构** 展示，**层次清晰**（键名、字符串、数字、`null`/布尔等 **分色或区分样式** 均可，以实现可读为准）。
- **对象、数组** 支持 **折叠 / 展开**（如 ▶/▼）；提供 **「全部展开」「全部折叠」** 快捷操作。

#### 5.3.3 查找与替换（键名 + 字符串值）

| 项 | 说明 |
| --- | --- |
| 查找 | 在 **键名** 与 **所有字符串类型的值** 中查找子串；命中处 **高亮**（如 `<mark>`）；支持可选 **忽略大小写**。 |
| 替换 | 提供「要替换的子串」「替换为」（**替换为可留空**）；**全部替换** 在 **对象键名** 与 **JSON 字符串值** 内做子串替换（**数组下标不变**）。替换后 **重新渲染** 树并保持与查找逻辑一致。 |
| 交互 | 查找输入宜做 **防抖**，避免大文档频繁重绘卡顿。 |

#### 5.3.4 其它

- **复制 JSON 文本**：复制当前内存中对象经 **2 空格** 格式化后的完整字符串。
- **压缩为一行（minify）**：仍不作为必选验收项；若实现可列为增强。

### 5.4 时间与时间戳互转

#### 5.4.1 Unix 时间戳 → 可读时间

| 项 | 说明 |
| --- | --- |
| 输入 | 同时支持 **10 位（秒）** 与 **13 位（毫秒）**；通过单选项指明 **输入含义**，**默认「秒」**。 |
| 展示时区 | 结果按 **浏览器本地时区** 格式化为可读日期时间。 |
| 输出 | 人类可读字符串（含日期与时间）。 |
| 非法输入 | 非数字、越界等需有清晰中文提示。 |

#### 5.4.2 北京时间 → Unix 时间戳

| 项 | 说明 |
| --- | --- |
| 语义 | 用户输入的日期时间一律按 **北京时间（东八区，Asia/Shanghai）墙钟** 理解，**与操作系统时区设置无关**。 |
| 输入格式 | 文本 **`YYYY-MM-DD HH:mm:ss`**；**秒可省略**（按 `:00` 处理）。 |
| 默认填充 | 打开页面或点击「填入当前北京时间」时，将输入框填为 **当前北京时间**（由实现使用 `Asia/Shanghai` 计算，避免依赖本机时区误解）。 |
| 输出 | 用户选择输出 **秒** 或 **毫秒** 的 **整型时间戳**（字符串或数字展示均可，语义明确即可）。 |
| 复制 | 提供 **复制时间戳**（纯数字）。 |
| 非法输入 | 格式不合法时明确提示。 |

### 5.5 整数进制转换

| 项 | 说明 |
| --- | --- |
| 能力 | **二进制、十进制、十六进制** 无符号/有符号整数互转（以 **十进制支持负整数** 为常见实现；二进制/十六进制输入以实现约定为准，需在界面说明）。 |
| 输入 | 用户选择 **当前输入进制**，在输入框填写；可支持可选前缀 **`0b`（二进制）、`0x`（十六进制）**。 |
| 输出 | 同时展示三种进制下的等价表示（实现可对过长位数做上限提示，避免性能问题）。 |
| 实现建议 | 使用 **`BigInt`** 等避免大整数精度丢失；非法字符需中文提示。 |

### 5.6 文本比较（含 JSON 结构化对比）

#### 5.6.1 通用能力

- 提供 **左右两个输入区**，输入两段待比较内容。

#### 5.6.2 纯文本模式

- 对比粒度建议为 **字符级**（或与实现等价的细粒度 diff），以保证与两侧原文对应关系清晰。
- **结果展示** 与输入布局一致：**左右两个结果框**（与「左侧内容」「右侧内容」对应）。
- **仅差异处** 使用 **红色标记**（如红底或红字）；**相同内容不做任何高亮或底色**。
- 左右结果区宜支持 **滚动位置同步**，便于对照长文本。

#### 5.6.3 JSON 模式

- 当用户选择按 **JSON** 比较时，两段输入均视为 **JSON 字符串**；需先 **JSON.parse**；解析失败时明确提示，不进行结构对比。

#### 5.6.4 比较模式

| 模式 | 说明 |
| --- | --- |
| **严格** | **顺序与内容**均需一致：对象键顺序、数组元素顺序均参与比较；不一致处需可识别。 |
| **非严格** | 对 **对象**：键顺序忽略，按键值语义比较。对 **数组**：**顺序无关**，按 **多重集合（multiset）** 语义比较——相同元素出现次数一致即视为该层级一致。 |

#### 5.6.5 差异展示（JSON）

- 要求 **结构化 diff**：以 **JSON 路径** 等方式标出不一致（字段路径、缺失/多余/值不同等），而非仅单一混排文本流。

### 5.7 RGB ↔ 十六进制颜色互转

| 项 | 说明 |
| --- | --- |
| 输入模式 | **RGB 与 Hex 二选一**：通过单选项切换；切换时 **自动清空** 未选中侧输入框，避免混填。 |
| RGB → Hex | RGB 输入形式 **仅支持** `R,G,B` 三个 0–255 整数，**英文逗号分隔**（示例：`255,255,255`）。页面需有 **固定说明文案**，避免用户误用 `rgb(...)` 等形式。 |
| Hex → RGB | 支持 **带 `#` 与不带 `#`** 的十六进制；支持 **6 位**；**3 位简写**（如 `#abc`）建议支持以提升体验。 |
| 结果展示 | 转换后在 **独立结果区** 同时展示 **HEX 与 RGB** 文本（不必回填到「另一侧」输入框，以免违背二选一原则）；**颜色块预览** 保留。 |
| 复制 | 提供复制（可为单行组合文案，如 HEX + RGB）。 |
| 非法输入 | 明确提示（越界、格式错误等）。 |

### 5.8 页面组织

- 所有工具位于**同一站点/应用**内，通过 **侧栏导航或分区** 进入各工具，分类清晰。
- 侧栏在宽屏下可 **固定左侧**、内容过多时 **侧栏内部滚动**（以实现为准）。
- 无需「搜索 / 收藏 / 最近使用 / 拖拽排序」等能力（未在本次需求中要求）。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 浏览器 | **仅考虑 Google Chrome** 兼容与测试。 |
| 离线 | **需要离线可用**：建议采用 **PWA（Service Worker 缓存静态资源）** 或等价方案，使用户在 **至少成功联网打开过一次** 后，可在无网络环境下继续使用（不调用任何后端接口）。 |
| 安全与隐私 | 所有计算在客户端完成；**不上传**用户文件与文本到服务器（本项目无登录无后端时自然满足）。 |
| 部署 | **静态资源托管**即可（如 nginx、对象存储静态站点等）；技术栈由研发选型（如 Vite + PWA 插件等）。 |
| 性能 | 200 MB 文件 MD5 在合理硬件下可完成；超大 JSON/文本比较可提示可能影响性能或做合理上限（文案或软限制）。 |

## 7. 验收标准（摘要）

1. 第 5 节所列工具均可按说明正确使用，错误输入有清晰中文提示。  
2. 文件 MD5：选择 + 拖拽，≤200MB，结果可复制，小写 MD5。  
3. 文本 MD5：UTF-8，结果可复制，小写 MD5。  
4. JSON：解析失败有提示；成功则为 **可折叠树** + **查找高亮（含可选忽略大小写）** + **字符串值全部替换** + **2 空格复制**。  
5. 时间：**时间戳→本地可读时间**（秒/毫秒解释正确）；**北京时间文本→时间戳**（格式与东八区语义正确），默认/一键填入当前北京时间，可复制时间戳。  
6. 进制：二/十/十六进制互转结果正确，非法输入有提示。  
7. 文本比较：**纯文本** 为左右双栏、**仅差异红标**、相同无标记，宜支持滚动同步；**JSON** 下严格/非严格符合 5.6.4，路径级结构化展示。  
8. 颜色：**RGB / Hex 二选一** 与清空规则；结果区展示 HEX+RGB 与预览；Hex 支持 `#` 与简写（建议）。  
9. 全站中文；无登录；Chrome 下离线可用（按第 6 节约定验证）。

## 8. 需求追溯（对齐记录摘要）

- 个人使用、无角色；按需打开；独立页面。  
- 工具均为本页小工具；随迭代补充进制转换、双向时间、JSON 树与比较展示优化等。  
- 无登录、无配置、无环境维度。  
- 不含内网与敏感参数场景。  

---

## 9. 开放项（实现期细化）

- Toast、空状态、主题色等细节由实现自定。  
- JSON 解析错误是否定位行列、minify 按钮、进制负数在二进制/十六进制下的展示形式等，可由实现补充说明。  
- 设计稿 HTML（`docs/ui-design-测试工具聚合页.html`）仅供视觉参考，以实际页面为准。
